## 2. 機能仕様

### 2.1 画面

1. **ホーム `/`**
   - 「問題一覧から選ぶ」「ランダムに1問」「つづきから（前回の続き）」「学習ノート」
   - 進捗サマリ（正解数 / 全19問、セクション別バー）
2. **問題一覧 `/problems`**
   - セクション（1.1〜1.4）× 例題/課題でグルーピング
   - 状態バッジ: 未挑戦 / 挑戦中 / 正解 / 要復習（惜しい）
   - フィルタ: すべて / 未正解のみ / 例題のみ
3. **出題画面 `/problems/[id]`**
   - 左: 問題文（＋自作SVG図）、入力仕様、入力例と期待値、ヒント（折りたたみ）
   - 右: コードエディタ（Cシンタックスハイライト、行番号、Tab=スペース4）
   - ボタン: 判定する / ひな形に戻す / 次の問題（コードは自動で一時保存）
   - 判定結果パネル: 合否、点数、良かった点、間違いの指摘（行番号つき）、考え方のヒント、**模範解答との違い**、次にやること
   - 解答例は判定後に `/api/solution` から取得して自動表示（初期HTMLには含めない）
4. **学習ノート `/notes`**
   - Drive の「プログラミングノート」「注意点」を整形して掲載（基本構造、`;` `\n` インデント、`%d/%f/%lf`、`%N.Mf`、キャスト、整数除算、math.h、ファイル名規則、手書き文字の書き分け、フローチャート記号）
5. **進捗のバックアップ `/progress`**
   - localStorage の進捗を JSON でダウンロード / コピー / 復元 / リセット

### 2.2 出題・判定フロー

1. 問題を選ぶ（一覧 or ランダム）→ エディタにテンプレ（`#include <stdio.h>` と `int main(void){ }` の骨組み）を挿入
2. ユーザーがコードを書く
3. 「提出して判定」
   - **①クライアント側の静的チェック**（即時・無料・APIキー不要）
   - ②`POST /api/judge` に `{problemId, code}` を送信 → サーバが Sarashina を呼ぶ
   - ③結果を表示し、履歴に保存
4. 「解答例を見る」で Drive の解答を表示（判定前は伏せ字、判定後に解放）

### 2.3 静的チェック（AIの前に決定的に弾く）

ノートの注意点をそのままルール化。文字列リテラル・コメント内は除外して検査する。

- 全角文字・全角スペースの混入（`printf("...")` の中身は許可）
- `int main(void)`（または `int main()`）が無い / `return 0;` が無い
- `#include <stdio.h>` が無い
- `scanf` の引数に `&` が無い
- `{` `}` の対応が取れていない
- 文末セミコロン漏れの疑い（行末が `;` `{` `}` `)` 以外で、`#` 行・コメント・文字列連結行でない）
- 整数除算の疑い（実数問題なのに `/ 2` のような整数定数で割っている）

→ エラーがあればその場で表示（ただし**提出はブロックしない**。最終判断はAI）。

### 2.4 ランダム出題

- ホームの「ランダムに1問」で、未正解の問題を優先して1問選ぶ（全問正解なら全問から）。
- 出題画面の「次の問題へ」で連続出題。
- （将来案）範囲を選べる: 全19問 / 1.1のみ / … / 課題のみ。

### 2.5 進捗保存（案）

- `localStorage`（ログイン不要・サーバ不要）
  - 保存内容: 問題IDごとの最終コード、判定結果、正解フラグ、試行回数、最終更新日時
  - 「履歴をエクスポート/インポート（JSON）」でバックアップ

## 3. AI判定仕様

### 3.1 呼び出し

- エンドポイント: `POST https://api.sarashina.ai/v1/chat/completions`
- 認証: `Authorization: Bearer $SARASHINA_API_KEY`（**サーバ側のみ。クライアントに絶対出さない**）
- モデル: `sarashina3-mini`（既定・精度重視／6リクエスト/分）
  - 速度優先の切替として `sarashina3-nano`（画面のプルダウンで選択）
- パラメータ: `max_completion_tokens`（**`max_tokens` は400エラー**）、`temperature 0.2`、`top_p 1`、`frequency_penalty 0.3`、`response_format`（JSON Schema）
  - `top_p` を 0.8 に絞ると、まれな漢字（徳・刀など）のトークンが候補から落ちて文字化けしたため 1 にする
  - `frequency_penalty` は nano が空白行を延々と繰り返す劣化を防ぐために入れる
- レート制限: 429 が返ったら待って再試行（`Retry-After` は無いので指数バックオフ）。UI に「混み合っています（最大60秒待ち）」を表示
- **日本国外IPは403**。ローカル実行・国内リージョンでのホスティングが前提（Vercel なら `hnd1`）

### 3.2 判定プロンプト（要点）

system:
- あなたはC言語入門（大学1年・第1章）の採点者。対象は `printf` / `scanf` / 四則演算 / `double` / `math.h` まで。if文・ループは未習。
- **解答は無数にある。模範解答と違っても、問題文の要件を満たしていれば正解**（変数名・printf の文言・桁指定の好みは減点しない。ただし問題文で指定された値・書式は満たすこと）。
- 実行はできないので、**コードを手で追跡**して出力を求める。入力例が与えられたら、その入力での出力を具体的に示す。
- 間違いは「どの行の・何が・なぜ」を初心者にわかる言葉で。答えを丸写しするのではなく、まず考え方を示す。
- 出力は必ず指定のJSONスキーマ。

user（サーバが組み立て）:
- 問題文（Drive由来の原文）
- 入力仕様・入力例・**期待される出力（こちらで計算した正解値）**
- 採点チェックリスト（例: 「scanf で3つ読む」「120*a+230*b+210*c」「総額を出力」）
- よくある間違い（例: `/2` の整数除算、`&` 忘れ、`%d` で double）
- 模範解答コード（Driveの `.c`）
- ユーザーのコード

### 3.3 レスポンス（JSON Schema）

```json
{
  "verdict": "correct | mostly_correct | incorrect",
  "score": 0-100,
  "summary": "1〜2文の結論",
  "good_points": ["..."],
  "issues": [
    { "severity": "error|warning|nit", "line": 12, "code": "該当部分", "message": "何が問題か", "fix_hint": "どう直すか" }
  ],
  "output_check": { "actual": "総額 = 910 円", "match": true },
  "hint": "答えを言わない次の一手",
  "model_answer_note": "模範解答と発想が違う点（あれば）"
}
```

- `score` は表示用。合否は `verdict`
- `output_check.actual` は「入力例に対する学生コードの出力」を1つの文字列で（改行は `\n`）。**期待される出力はモデルに書かせない**（文字起こしが崩れるため、サーバが教材データから補完する）
- `issues[].line` は行番号（エディタ上でハイライト）
- パース失敗時は1回だけ再試行（温度を上げる）→ それでもダメなら 502 でエラー表示

### 3.4 API 設計（Next.js Route Handler）

- `POST /api/judge` … body `{ problemId, code }` → 上記JSON
  - 入力検証（問題IDの存在、コード長 20,000字以内）
  - 問題文・解答・チェックリストはサーバ側の `problems.json` から取得（クライアントから改ざん不可）
- `GET /api/health` … Sarashina への疎通確認（キー未設定なら 503 とメッセージ）

## 4. データ構造（`src/data/problems.ts` または JSON）

```ts
type Problem = {
  id: string;                 // "k-1-2a"
  section: "1.1" | "1.2" | "1.3" | "1.4";
  kind: "example" | "task";
  label: string;              // "課題 1.2.a"
  title: string;              // 一覧に出す短い名前
  statement: string;          // 問題文（原文ベース）
  inputSpec: string | null;   // 入力の説明
  sampleInputs: string[];     // ["3 2 1"]
  expectedOutputs: string[];  // ["総額 = 910 円"]
  figure?: "star" | "triangle" | "parallel-resistor";
  hints: string[];
  checkpoints: string[];      // 採点チェックリスト
  commonMistakes: string[];   // よくある間違い
  referenceCode: string[];    // 模範解答（複数可）
  notesRef?: string[];        // 関連ノートの見出し
};
```

`expectedOutputs` は**こちらで計算した正解値**（例: k-1-2a, 入力 `3 2 1` → 120*3+230*2+210*1 = 1030）。AIにはこれを渡して「出力が一致するか」を判定させる。

## 5. 技術スタック（決定）

**「PCのサーバ起動不要・無料公開・APIキー秘匿」を満たす構成**

- **Next.js 15（App Router）+ TypeScript + Tailwind CSS**
- **Vercel（Hobby / 無料）にデプロイ**。静的ページ＋サーバレス関数1本（`/api/judge`）
  - **関数リージョンは `hnd1`（東京）を指定**。Sarashina は日本国外IPを403で拒否するため必須
  - APIキーは Vercel の環境変数 `SARASHINA_API_KEY` に保存（リポジトリには入れない）
- エディタ: **CodeMirror 6**（`@codemirror/lang-cpp`）。行番号・色分け・自動インデント・指摘行のハイライト
- 状態/保存: **`localStorage`**（ログイン不要・DB不要、無料運用）。JSONエクスポート/インポート付き
- サーバ: Route Handler から `fetch` で Sarashina を直接呼ぶ（SDK不要）
- 判定モデル既定: **`sarashina3-mini`**（画面の設定で `nano` に切替可）
- 解答例: **判定後に開放**
- ローカル確認は `npm run dev`、公開は `vercel deploy`（どちらもPC常時起動は不要）

## 6. 決定事項と残り

### 決定
1. スタック: Next.js + TS + Tailwind / Vercel（`hnd1`）
2. エディタ: CodeMirror 6
3. 保存: localStorage
4. 判定モデル: `sarashina3-mini`（既定）
5. 解答例: 判定後に表示
6. フォルダ: `programming-practice`（表示名「プログラミング練習」）

### 残り（実装前に必要なもの）
1. **Sarashina API キー**（`SARASHINA_API_KEY`）。ローカルの `.env.local` と Vercel 環境変数の両方に設定
2. 図1.1（三角形）・図1.2（並列回路）・1.1.b の星模様は原本PDFに図が無いため、解答コードから仕様を起こして**SVGを自作**する（文言で問題文に補足）

### 補足: 無料公開での注意
- Vercel Hobby は商用利用不可・月間の関数実行時間に上限あり（個人練習用途なら十分）
- 誰でもURLにアクセスできるため、**過剰な連打対策**として `/api/judge` に簡易レート制限（同一IPあたり例: 10回/分）とリクエスト長の上限を入れる
- Sarashina 側の上限（mini: 6リクエスト/分）と二重にかかるので、429 は待って再試行し、UIに待ち時間を表示
